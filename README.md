# Sir Fred: Quality of Life Edition

Модификация машинного кода оригинальной **Sir Fred** (Made in Spain / Mikro-Gen, 1986,
ZX Spectrum 48K). Графика, карты, загадки и физика остались прежними — смягчены только
слишком строгие требования к точной позиции Фреда.

Готовая игра: **`build/Sir_Fred_QoL.z80`** (снимок 48K, тот же формат и то же состояние
процессора, что у оригинала; стартует в меню).

> **Оригинальные ROM-файлы не включены в репозиторий** (авторские права).
> Для сборки положите в `original/`:
> * `SirFred.z80` — оригинальный снимок игры;
> * `Sir_Fred_RAM_48K_verified.bin` — дамп RAM 48K (можно получить из снимка
>   командой `python tools/z80snap.py original/SirFred.z80 --ram original/Sir_Fred_RAM_48K_verified.bin`).

## Что изменено

| | было (измерено в оригинале) | стало (по умолчанию) |
|---|---|---|
| **Захват верёвки/лианы в прыжке** | одна клетка карты: 4 позиции X (8 px), строго в ряду головы | диапазон ±4 px от края Фреда, ряды головы и груди: 8 позиций; после захвата Фред притягивается к верёвке, как и раньше; сквозь стены нельзя |
| **«Вниз» на краю — слезть на лиану** | 4 позиции X | 8 позиций; позиция Фреда мягко поправляется, спуск идёт по оригинальной анимации |
| **Подбор предмета (Z)** | \|ΔX\| < 16 | \|ΔX\| < 20, по вертикали вниз 20 (вверх без изменений) |
| **Использование предмета (M)** у цели | пересечение рамок | рамка Фреда +4 px с каждой стороны — только для обработчиков предметов, не для врагов |
| **Coyote time** | после схода с края прыжок невозможен | можно прыгнуть в течение ~5 кадров (6 тиков) после схода, с той же инерцией |
| **Раскачка на верёвке** | затухает за несколько качков, максимальная фаза 5 | не затухает, стартовая фаза 8, ручная подкачка до 8, порог скорости 1 |
| Инерция разворота | порог 8 | не изменена (настраивается, выключено) |

Подробности, адреса и байты — [docs/REVERSE_ENGINEERING.md](docs/REVERSE_ENGINEERING.md).

## Запуск

Откройте `build/Sir_Fred_QoL.z80` в любом эмуляторе ZX Spectrum 48K (Fuse, ZXSpin,
Spectaculator, SpecEmu, Unreal Speccy, онлайн-эмуляторы с поддержкой .z80), режим 48K.

Меню: `1` Kempston, `2` Cursor, `3` переопределить клавиши, `4` клавиатура, `0` старт.
Клавиши по умолчанию: **Q** вверх/прыжок, **A** вниз, **O** влево, **P** вправо,
**M** использовать предмет, **Z** подобрать / выбрать слот, **SPACE** выход.

## Сборка

Нужно: Python 3.10+, `pip install skoolkit` (симулятор для тестов) и sjasmplus 1.21
(для Windows лежит в `tools/bin/`; на других системах положите `sjasmplus` в `tools/bin/`).

```
python tools/build.py          # -> build/Sir_Fred_QoL.z80, build/patch_report.txt
python tests/run_all.py        # все тесты
```
или `make` / `make test` (`mingw32-make` на Windows).

Процесс сборки:
1. проверка SHA-1 `original/SirFred.z80` и совпадения его RAM с `original/Sir_Fred_RAM_48K_verified.bin`;
2. sjasmplus загружает исходную RAM и накладывает `patches/*.asm`; перед каждой правкой
   проверяются исходные байты (`EXPECT`), переполнение свободной памяти — ошибка;
3. `tools/build.py` пишет `.z80` с **исходным заголовком** (регистры, IM, бордюр) и новой RAM,
   перечитывает и сверяет результат, печатает все изменённые байты.

Распаковать память оригинала: `python tools/z80snap.py original/SirFred.z80 --ram out.bin`.

## Настройка

Всё — в [`qol.cfg`](qol.cfg), затем пересборка. Каждый патч отключается своим `QOL_*=0`;
при всех нулях результат побайтно равен оригинальному файлу (проверяется тестом).

| параметр | по умолчанию | оригинал | диапазон |
|---|---|---|---|
| `QOL_ROPE`, `ROPE_FWD`, `ROPE_BACK`, `ROPE_ROWS` | 1, 4, 4, 2 | 0, 0, 1 | 0–8, 0–8, 1–3 |
| `QOL_DESCEND`, `DESC_TOL` | 1, 4 | 0 | 0–6, чётное |
| `QOL_PICKUP`, `PICK_X`, `PICK_Y_LOW`, `PICK_Y_HIGH` | 1, 20, 20, 24 | 16, 16, 24 | 16–24, 16–24, 24–28 |
| `QOL_USE`, `USE_TOL` | 1, 4 | — | 1–6 |
| `QOL_COYOTE`, `COYOTE_TICKS` | 1, 6 | — | 1–16 (2–3 тика на кадр) |
| `QOL_INERTIA`, `TURN_SPEED` | 0, 8 | 8 | 1–32 |
| `QOL_SWING`, `SWING_NO_DAMPING`, `SWING_MAX_PHASE`, `SWING_PUMP_CAP`, `SWING_SPEED_THRESHOLD` | 1, 1, 8, 8, 1 | 0, 0, 5, 7, 10 | 0/1, 0/1, 1–8, 1–8, 1–255 |

Разовая сборка с другим значением: `python tools/build.py -D ROPE_FWD=6`.

## Что проверено

Тесты запускают игру в эмуляторе (SkoolKit: Z80 + ПЗУ 48K + прерывания 50 Гц) и сравнивают
поведение с оригиналом:

* `test_build` — формат и заголовок снимка, сборка каждого патча отдельно, «всё выключено»
  = оригинал, все изменения только в объявленных местах;
* `test_window` — ужатая часть построителя окна столкновений эквивалентна оригиналу на всех 49 152 позициях;
* `test_rope`, `test_descend`, `test_pickup`, `test_coyote`, `test_inertia` — окна срабатывания
  в оригинале и QoL, совпадение конечных позиций, стены, режимы «как в оригинале»;
* `test_use` — рамка использования (на уровне процедур);
* `test_sessions` — записанные сессии (3 комнаты, верёвка, яма, лиана, вода): освобождённая
  память не используется оригиналом; QoL-сборка проходит маршрут до водной комнаты;
* `test_listing` — аннотированный листинг собирается обратно в оригинальные байты.

**Не проверено:** игра в GUI-эмуляторе человеком; прохождение конкретных загадок с
предметами; комнаты дальше третьей. Буфер прыжка не реализован — не хватает свободной памяти.

## Структура

```
original/      исходные файлы (не изменяются)
tools/         z80snap (чтение/запись .z80), build, emu (эмулятор), memusage, deadcode,
               xref, z80dis, mklisting; bin/sjasmplus.exe
patches/       main.asm (сборка и параметры), symbols.asm (адреса и свободная память),
               rope_grab, rope_swing, vine_descend, window_compact, items, coyote, inertia
disassembly/   sirfred_core.asm — аннотированные процедуры, пересобираются в оригинал
tests/         тесты, sessions/ — сценарии игры, make_sessions.py — их генератор
docs/          REVERSE_ENGINEERING.md
build/         результат сборки (создаётся)
```
