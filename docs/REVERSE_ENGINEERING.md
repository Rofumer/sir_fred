# Sir Fred (Mikro-Gen re-release, 1986) — reverse engineering

Документ фиксирует всё, что найдено в коде игры, как это проверялось и что изменено в
Quality of Life Edition. Адреса — шестнадцатеричные, адресное пространство ZX Spectrum 48K.
Аннотированный листинг ключевых процедур, который пересобирается в оригинал побайтно:
[`disassembly/sirfred_core.asm`](../disassembly/sirfred_core.asm).

Обозначения статуса:
**[подтверждено]** — проверено в эмуляторе (поведение или трассировка);
**[статически]** — видно из кода, динамически не проверялось;
**[гипотеза]** — правдоподобно, не доказано.

---

## 1. Исходные файлы

| файл | SHA-1 | содержимое |
|---|---|---|
| `original/SirFred.z80` | `2030d767b6f9539d925de8b0596091930d356d9c` | снимок, 41 827 байт |
| `original/Sir_Fred_RAM_48K_verified.bin` | `75ffcd45e285048d78ed2f4e7f04dd3b11b8878c` | RAM 4000–FFFF, 49 152 байта |

**Формат snapshot** [подтверждено]: Z80 версии 2 (в основном заголовке PC=0, дополнительный
заголовок 23 байта), аппаратный режим 0 = 48K, три сжатые страницы: 8 → 4000, 4 → 8000,
5 → C000. Распаковка `tools/z80snap.py` даёт RAM, побайтно равную BIN-дампу.
Повторная упаковка с исходным заголовком даёт файл того же размера.

**Состояние процессора в snapshot** [подтверждено]:

| регистр | значение | | регистр | значение |
|---|---|---|---|---|
| PC | 0038 (вход в обработчик IM 1 ПЗУ) | | SP | FFED |
| AF | 42 04 | | AF' | 04 02 |
| BC | 0000 | | BC' | 5300 |
| DE | 44CE | | DE' | F800 |
| HL | 3E7C | | HL' | E72E |
| IX | 5B93 | | IY | 5C3A (системные переменные) |
| I | 3F | | R | 64 |
| IM | 1 | | IFF1/IFF2 | 0/0 (прерывание только что принято) |
| бордюр | 0 | | | |

Снимок сделан в меню (`1 KEMPSTON / 2 CURSOR / 3 REDEFINE / 4 KEYBOARD / 0 START`), стек
содержит возврат в процедуру печати ПЗУ. Игра пользуется IM 1 и обработчиком ПЗУ (счётчик
FRAMES 5C78, KSTATE), печать меню и цифр инвентаря — через `RST $10`.

## 2. Инструменты

* **SkoolKit 10.1** (pip) — C-симулятор Z80 с ПЗУ 48K, дизассемблер.
* **sjasmplus 1.21** (`tools/bin/`) — ассемблер патчей, режим `DEVICE ZXSPECTRUM48`.
* `tools/emu.py` — безголовый эмулятор: покадровый запуск с прерываниями 50 Гц, клавиатура,
  сохранение/восстановление состояния, PNG-скриншоты, пошаговая трассировка.
* `tools/memusage.py` — Python-симулятор с инструментированной памятью: какие байты
  читаются/пишутся/исполняются за сценарий игры.
* `tools/z80dis.py`, `tools/xref.py`, `tools/deadcode.py`, `tools/mklisting.py` —
  дизассемблер, перекрёстные ссылки, поиск мёртвого кода, генерация листинга.

Методика: каждая переменная найдена сравнением RAM при удержании клавиш, каждая процедура —
от точки опроса клавиатуры по цепочке вызовов, каждая гипотеза о поведении — экспериментом
«поставить Фреда в X, нажать клавишу, посмотреть результат» на оригинале.

## 4. Главный цикл и ввод

**Главный цикл** `E966` [подтверждено]: задержка `LD BC,$0190 / CALL $80F1`, обновление
объектов комнаты, затем выбор состояния. Длительность тика — около 0,3–0,5 кадра
(2–3 тика за кадр 50 Гц, измерено остановкой на E966).

Порядок в цикле (E9F2–EB1F):

1. SPACE (`7F/бит 0`) — выход; **Z** (`9FBE`) → `99AE` подбор/смена слота.
2. Особые состояния: плавание (`98FB`), анимации `923C`, `871D`, `924C`, оглушение `8418` …
3. `EAC3`: если `FRED_AIR ($849C) ≠ 0` → `JP $90F5` (обработчик полёта; клавиши не читаются!).
4. `EAD7` — тик на земле: `XOR A / LD ($923A),A`, затем **M** (`9FD3`) → использование
   предмета `EB2C`, **A** → `8FFB`, **Q** → `9072`, **O** → `8F28`, **P** → `8E68`,
   иначе `8E3A` (покой).

**Клавиши** [подтверждено]: заглушки по 7 байт `LD A,ряд / IN A,($FE) / AND маска / RET`,
результат Z = нажата. Пункт меню «REDEFINE KEYS» переписывает ряд/маску.

| заглушка | порт/бит | клавиша | действие |
|---|---|---|---|
| 9FBE | FE/1 | Z | подобрать / сменить слот |
| 9FC5 | DF/0 | P | вправо |
| 9FCC | DF/1 | O | влево |
| 9FD3 | 7F/2 | M | огонь / использовать предмет |
| 9FDA | FD/0 | A | вниз |
| 9FE1 | FB/0 | Q | вверх / прыжок |

`6509–6532` — **мёртвая старая копия диспетчера** с теми же вызовами `9FDA/9FE1/9FCC/9FC5`,
обрывается на `CALL $8206`, ссылок нет [подтверждено: заливка `RST 0` не меняет игру].

## 5. Координаты и переменные Фреда

Координаты — пиксели экрана, одна точка = один пиксель; знакоместо = `X>>3`, `Y>>3`.
X — левый край спрайта 16×24, Y — верхний край. По X Фред ходит шагом 2 пикселя.

| адрес | имя | смысл | статус |
|---|---|---|---|
| 8496 | FRED_X | X, 2..238 в пределах комнаты; за краем — смена комнаты (EB92) | подтверждено |
| 8497 | FRED_Y | Y; 64 — пол комнаты 1 | подтверждено |
| 8498/8499 | FRED_OLD | позиция, где спрайт нарисован (по ней он стирается) | подтверждено |
| 849B | FRED_SPEED | инерция: растёт при удержании (наблюдалось до 175), делится на 4 при прыжке и сходе с края | подтверждено |
| 849C | FRED_AIR | в воздухе: 1 — прыжок, $20 — сход с края | подтверждено |
| 84A7 | FRED_DIR | 0 — влево, 1 — вправо | подтверждено |
| 8431 | JUMP_VEL | вертикальная скорость (фиксированная точка) | подтверждено |
| 8432 | JUMP_RISING | 1 — фаза подъёма | подтверждено |
| 8434 | JUMP_ACC | дробная часть: при переполнении — шаг 2 px | статически |
| 8417 | TUMBLE | после долгого падения: захват верёвки запрещён | статически |

| 871E/871F | ROPE_INDEX/SEG | номер верёвки и сегмент | подтверждено |

## 6. Карта столкновений и «окно»

`B3B0` — 32×20 байт на комнату, по байту на знакоместо [подтверждено]:

| бит/значение | смысл |
|---|---|
| бит 0 | твёрдое (стена/пол) |
| `(v & $C5) == $04` | можно схватиться (верёвка, лиана); `v>>3` — номер в ROPE_TABLE |
| `$44` | клетка над лианой, с которой можно слезть вниз |
| `$82` | склон |

Комната 1: `$01` — земля, `$0C` — верёвка №1 (столбец 13, ряды 4–8), `$14` — лиана №2
(столбец 19, ряды 11–15), `$44` — (10,19) и (11,18). Клетки верёвки двигаются вместе с ней
при раскачке (`89CB` пишет `$0C`).

**Окно** `8751` [подтверждено трассировкой]: копирует 5 рядов × 4 клетки вокруг Фреда в
`841B` (ряды Y/8−1…Y/8+3, столбцы X/8−1…X/8+2), запоминает `X&7`, `Y&7` в `841A/8419`.
Код разбросан переходами между `87xx` и `67xx` (8751 → 67B2 → 8758 → 67ED → 8768 → 67DF →
8779 → 67B9). На выходе HL указывает в карту на (Y/8−1, X/8−1) — это используют патчи.
Хвост `67B9–67D5` содержит лишние инструкции, результат которых перетирается
(подробно в `patches/window_compact.asm`). Вход `8754` попадает в середину
`LD BC,($8496)` и исполняет байт `$84` (`ADD A,H`) — вероятно, намеренная экономия.

## 7. Механики

### 7.1 Захват верёвки — `879A` (главная причина пиксельхантинга)

Вызывается каждый тик полёта из `91AC` (если `TUMBLE = 0`), а также из `7E49`, `A53E`,
`EC3C`, `EC73` (сход с верёвки, смена комнаты).

```
879A CALL $8751              ; окно
879D LD A,($84A7) ...        ; C = 7 (вправо) или 5 (влево)
87A8 LD ($87B4),A            ; самомодификация смещения
87B2 LD A,(IX+n)             ; ОДНА клетка: ряд Y/8, столбец (X+16)/8 или X/8
87B6 AND $C5 / CP $04 / JR NZ,$87AD
87BC ROPE_ON=1, ROPE_INDEX=v>>3; 87E2 поиск сегмента по Y; 8803 притягивание к верёвке
```

Измерено (Фред под верёвкой комнаты 1, прыжок вертикально): захват **только при X 88–94**
(лицом вправо) и **104–110** (влево) — 4 позиции шага 2 px. После захвата Фред всегда
ставится в одну точку (94,58)/(102,58): игра сама корректирует позицию, т.е. проблема только
в узости окна проверки. При разгоне «P k кадров → остановка по инерции → прыжок» оригинал
попадает на верёвку в 2 из 40 случаев.

### 7.2 Спуск на лиану с уступа — `964F`

Клавиша «вниз» на земле (`9060 → 964F`): одна клетка ряда ног (Y/8+2), столбец X/8 (влево)
или (X+16)/8 (вправо) должна быть `$44`. Тогда `923C = $96`, и анимация `9669` за несколько
шагов разворачивает Фреда, выравнивает X по сетке (`9689`: `(X+8)&$F8` или `X&$F8`), опускает
его и в конце вызывает захват `879A` (через `A53E`).
Измерено: оригинал — X 152–158 (лицом влево), уступ при этом заканчивается на X≈146.

### 7.3 Подбор предметов — `99AE` / `99DB` / `9A32`

Z: `99AE` (антидребезг `98F7`), `99DB` перебирает `ROOM_ITEMS`, `9A32` проверяет
`|X−Xп| < 16` и `Yп−Y < 16` (предмет ниже верха Фреда) / `Y−Yп < 24` (выше). Найденный
предмет меняется местами с выбранным слотом; если ничего нет — выбирается следующий слот.
Измерено в комнате 2 (предмет X=97): подбор при X 82–112 — совпадает с формулой.
Вывод: подбор не «пиксельный», проверяется пересечение спрайтов.

### 7.4 Использование предметов — `EB2C`, `B78F`/`B773`

M: тип предмета из выбранного слота (`&$1F`) выбирает обработчик из таблицы `EB6E`
(самомодифицирующийся адрес, переход через `5B62`). Тип 3 — отдельно (`9C5E`).
Таблица: 1→6017, 2→8C8A, 4→75AC, 5→ECD9, 6→6687, 7→68EE, 8→5B62, 9→F122, 10→6419,
11→CBA5, 12→6494, 13→E6E6, 14→CCE5, 15–16→BA85 [статически].

`B78F` — рамка Фреда: HL=(X,Y), D=24, E=16 (в воздухе D=18, в воде 32×16, присед — Y+8);
`B773` — пересечение двух прямоугольников (HL,DE против HL',DE'), CY=пересекаются
[подтверждено вызовом в эмуляторе]. Используется обработчиками предметов 14 и 11 (`5F10`; тип 11 входит через `5F17`),
7 (`5FD5`), 10 (`6421`), 12 (`64A6`) и столкновениями с врагами/опасностями
(`B7B4` — список врагов `6D7B`, `BCBF`, `CB6F`, `CD6F`, `ED54`, `F0AF`).
Отдельная точная проверка объекта — `639D` (ряд Фреда == ряд объекта, столбец в [x, x+4)) —
используется объектом `6393` [статически, назначение объекта — гипотеза: движущийся
предмет головоломки].

### 7.5 Прыжок и падение

* старт прыжка `82F7` (из `CC6F`, Q на земле → `90E5`): `FRED_AIR=1`, скорость/4,
  `JUMP_VEL=$80`, `JUMP_RISING=1`; порог вершины `$20` (или `$08` при `8430`) —
  самомодификацией в `8398`;
* физика `8377–83C2`: накопитель `8434 += JUMP_VEL`, при переполнении шаг 2 px; на подъёме
  `v −= v/4`, на спуске `v += v/4 + 4` (до 255). Прыжок с места — около 10 px вверх;
* сход с края `828D` (из `8FC5`, когда `929A` вернул `$20` — нет пола): `JUMP_VEL=$20`,
  `FRED_AIR=$20`, скорость/4, `JUMP_RISING=0`, X сдвигается на 6–8 px;
* в полёте клавиша прыжка не читается вовсе (`EAC3` уходит прямо в `90F5`) — отсюда
  отсутствие «coyote time» [подтверждено: в оригинале Q после схода никогда не даёт прыжка];
* долгое падение: `FALL_TICKS` = $14 → `9860` (урон), `TUMBLE`.

### 7.6 Инерция и стены

* Ходьба `8E68`/`8F28`: при смене направления, пока `FRED_SPEED ≥ 8` (`CP $08` в
  `8EAD`/`8F6D`), Фред продолжает скользить — разворот через 38 кадров после 20 кадров бега
  [подтверждено].
* `92E9` — стена впереди: клетки столбца 3 (вправо) или 0 (влево) окна в рядах 1–3 и ряд 4
  при `Y&7≠0`, условие `(v & 5) == 1`. Удар на скорости ≥ 64 — оглушение (`8188`).
* `929A`/`CCAA` — пол под ногами, результат `$20` — пола нет.

## 8. Свободная память

Свободных блоков больше ~100 байт в игре нет. Найдено и использовано:

| блок | адреса | байт | откуда | проверка |
|---|---|---|---|---|
| F1 | 8692–8706 | 117 | `8692–869B` — мёртвые заглушки (`CALL $8698` внутри `$8698`), далее 107 нулей | нет ссылок; заливка RST 0 |
| F2 | 6509–6536 | 46 | мёртвая копия диспетчера + 4 нуля (6537+ — переменные) | нет ссылок; заливка RST 0 |
| F3 | 67C8–67D5 | 14 | освобождается ужатием хвоста окна | тест эквивалентности окна |
| F4 | A21E–A22A | 13 | нули между трамплинами `JP` и целью `A22B` | нет ссылок; заливка RST 0 |
| F5 | E842–E850 | 15 | недостижимый `CALL $E8DE` + 12 нулей | нет ссылок; заливка RST 0 |
| I1, I2 | 87A4–87AC, 87B2–87BB | 9+10 | старая проверка верёвки, не нужна после патча A | — |
| I3 | 8EA3–8EA9 | 7 | обрывок после `JP $6CE8` | нет ссылок; заливка RST 0 |
| I4 | 9293–9299 | 7 | обрывок после `JP $8206` | нет ссылок; заливка RST 0 |

Отвергнуты: `9898` (хвост таблицы адресов), `9900–997F` (буферы спрайта), `EFAD–F002`
(возможно, пустая графика — ссылки по указателям не исключены), `E89F` (буфер REDEFINE KEYS),
`FD00–FFC4` (данные комнат и UDG), `62BC`, `6D6A` (переменные).

«Ссылки» проверялись поиском каждого 16-битного слова во всей RAM и всех относительных
переходов; найденные совпадения просмотрены вручную (все оказались операндами чужих
инструкций или графикой). Динамика: `tools/memusage.py` по двум сессиям (2 686 кадров, три
комнаты, верёвка, лиана, яма, вода) — ни одного чтения/записи/исполнения в F1, F2, F4, F5,
I3, I4; `tests/test_sessions.py` заливает эти блоки `RST 0` в **оригинале** и требует
идентичного прохождения.
**Ограничение:** комнаты, не пройденные в сессиях, динамически не проверены; статическая
проверка ссылок покрывает всю память.

## 9. Подтверждённые и неподтверждённые гипотезы

Подтверждено: формат snapshot и регистры; карта клавиш; все переменные раздела 5 с пометкой;
формат карты и окна; окно захвата верёвки 88–94/104–110 и притягивание; окно спуска 152–158;
формула подбора; пересечение `B773`; отсутствие прыжка в полёте; порог заноса 8;
неиспользование свободных блоков в двух сессиях.

Не подтверждено / не исследовано:
* назначение объекта `6393` и проверки `639D`, обработчики предметов по отдельности —
  головоломки в сессиях не решались;
* `93CE` и `9339` меняются во время работы (самомодификация), статический вид неверен;
* смысл `849C = $18` (пишется в `8EE0`, `90BE`) и состояния `9248/9252/9255`.

## 10. Изменения QoL Edition

Все изменения — `patches/*.asm`, сборка `tools/build.py`, параметры `qol.cfg`.
Перед записью каждого участка `EXPECT` проверяет исходные байты; переполнение любого
свободного блока — ошибка сборки. Полный список байтов — `build/patch_report.txt`.
Ниже — конфигурация по умолчанию.

### A. Захват верёвки/лианы (`QOL_ROPE`, `ROPE_FWD=4`, `ROPE_BACK=4`, `ROPE_ROWS=2`)

| адрес | было | стало | ассемблер |
|---|---|---|---|
| 879D–87A3 | `3A A7 84 0E 07 A7 20` | `CD 92 86 20 0B 18 18` | `CALL qol_rope_scan / JR NZ,$87AD / JR $87BC` |
| 8692–86E7 | заглушки + нули | 86 байт | `qol_rope_scan` |

`qol_rope_scan`: от указателя окна (HL после `CALL $8751`) перебирает пиксели от
«края − BACK» до «края + FWD» (край = X+16 вправо, X влево) в `ROPE_ROWS` рядах от головы,
наружу от Фреда; первая клетка `(v&$C5)=$04` → Z, C=v и далее оригинальный код захвата и
притягивания; твёрдая клетка останавливает поиск в ряду (не сквозь стены). При 0/0/1 —
точно оригинальная проверка.
Проверка (`tests/test_rope.py`): окно 84–98 / 100–114 (8 позиций вместо 4), позиция после
захвата прежняя, вариант 0/0/1 совпадает с оригиналом, стена блокирует захват в обе
стороны, «естественный» подход 7/40 против 2/40.

### B. Спуск на лиану (`QOL_DESCEND`, `DESC_TOL=4`)

| адрес | было | стало | ассемблер |
|---|---|---|---|
| 964F–9668 | исходная проверка (26 байт) | новая (26 байт) | окно, ряд ног, первый пиксель, `JP qol_descend2` |
| 6509–6530 | мёртвый диспетчер | 40 байт | `qol_descend2`: пробы через 2 px, при попадании — смещение и `923C=$96` |
| 67B9–67C7 | хвост окна (29 байт) | 15 байт | эквивалентный хвост (см. ниже) |
| 67C8–67D4 | — | 13 байт | `qol_desc_fix` + переменная смещения |
| 969D–969F | `E6 F8 6F` | `CD C8 67` | `CALL qol_desc_fix` — к X прибавляется смещение перед выравниванием |

Мягкая коррекция: первый шаг анимации выравнивает X как будто Фред стоял на X+смещение;
стирание спрайта идёт по настоящей старой позиции, поэтому артефактов нет.

ужатый хвост окна даёт те же A, F, BC, DE, HL, IX, SP и буфер для всех 49 152 позиций.

### E. Coyote time (`QOL_COYOTE`, `COYOTE_TICKS=6`)

| адрес | было | стало | ассемблер |
|---|---|---|---|
| 828D–8291 | `3E 20 32 31 84` | `CD 1E A2 00 00` | `CALL qol_walkoff` (взводит счётчик, затем оригинал) |
| A21E–A229 | нули | 12 байт | `qol_walkoff` + переменная `qol_coyote` |
| EAD4–EAD6 | `C3 F5 90` | `C3 42 E8` | `JP qol_air1` вместо `JP $90F5` |
| EAD7–EADA | `AF 32 3A 92` | `CD F8 86 00` | `CALL qol_ground` (обнуляет и счётчик) |

### F. Порог заноса (`QOL_INERTIA=0` по умолчанию, `TURN_SPEED=8`)

`8EAE`, `8F6E`: операнд `CP $08`. По умолчанию не включено — инерция оригинальная.
Проверка (`tests/test_inertia.py`): 8 = оригинал (38 кадров до разворота), 32 — 1 кадр.

### G. Раскачка на верёвке (`QOL_SWING=1`)

Верёвка в оригинале — затухающий маятник: `$8874`‒`$88CB` каждый тик меняет амплитуду
(`$8723+5`, младший ниббл), а при развороте с малой фазой `$888E` делает `DEC ($8723+6)`,
постепенно гася качание.  Начальная фаза после приземления ограничена `5` (`$8A1E`),
а ручная подкачка кнопками O/P — `7` (`$8B14`).  Порог скорости для старта качания — `$0A`
(`$89E1`).

| адрес | было | стало | ассемблер |
|---|---|---|---|
| `$888E`‒`$8890` | `DD 35 06` | `00 00 00` | `NOP` x3: затухание отключено |
| `$8A1A`‒`$8A1B` | `FE 06` | `FE 09` | `CP SWING_MAX_PHASE+1` |
| `$8A1E`‒`$8A1F` | `3E 05` | `3E 08` | `LD A,SWING_MAX_PHASE` |
| `$8B14`‒`$8B15` | `FE 08` | `FE 09` | `CP SWING_PUMP_CAP+1` |
| `$89E1`‒`$89E2` | `FE 0A` | `FE 01` | `CP SWING_SPEED_THRESHOLD` |

По умолчанию качание не затухает, сразу разгоняется до безопасного максимума
(фаза 8 → амплитуда 7; таблица формы `$C9E7` имеет только 0‒7) и доступно даже при
малой скорости приземления.

### Не реализовано

* **Буфер прыжка (jump buffering)** — для него нужна ещё ~60 байт кода, свободной памяти не
  осталось. Удержание Q при приземлении и так даёт прыжок (оригинал читает Q каждый тик
  на земле), не помогает только раннее короткое нажатие.
* **Смягчение столкновений с врагами** — сознательно не делалось: расширение рамки упрощает
  жизнь только при «полезных» пересечениях, а рамка врагов — урон.
* **TAP** — не создавался: снимок сделан внутри обработчика прерываний с ПЗУ-стеком и
  экраном в памяти, корректный загрузчик должен восстановить все 48K и регистры поверх
  самого себя; оригинальная загрузка в снимке не сохранилась.
